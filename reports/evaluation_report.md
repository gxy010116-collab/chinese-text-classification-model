## 一、数据集构成

### 1.1 内置评测集（sample_data.json，211 条）

评测集为本仓库内置的固定数据集，不依赖任何外部下载。构造方式：按 10 个标签人工撰写/改写真实风格的中文新闻短文本标题（18–36 字符，中位数 25），覆盖典型表述与少量跨领域表述，用于检验模型在近似真实业务输入上的泛化能力。评测集与训练数据生成分离：训练数据由 `train.py` 的模板+关键词引擎在运行时生成，评测集是静态 JSON，二者来源不同。

|----|------|------|----|------|------|

| 1 | 科技 | 22 | 6 | 社会 | 21 |

| 3 | 体育 | 21 | 8 | 健康 | 21 |
| 4 | 娱乐 | 21 | 9 | 军事 | 21 |

### 1.2 训练数据（seed=42 模板生成，4000 条）

`train.py` 内置每个类别约 100 个领域关键词池 × 15 条句式模板，通过「模板 + 1~2 个关键词随机填充」生成训练样本，固定 `seed=42`（Python random + torch 全局种子）保证任何人重跑生成完全相同的数据。本次运行配置：每类 400 条共 4000 条，按 85/15 切分为训练集 3400 条 / 验证集 600 条（各类均衡）。

该方式的优点是无外部数据依赖、可复现、类别均衡；局限是句式与词表封闭，对训练分布外的真实长尾表述泛化有限——这直接解释了评测集上 15% 的错分（见第三节）。

## 三、错例与混淆对分析（共 32 条错例）

主要混淆对（真实→预测，条数）：科技→军事 5、军事→时政 4、社会→财经 3、房产→财经 3、教育→科技 2、时政→财经 2、社会→教育 2、健康→时政 2，其余为零散单条。逐条分析如下：

### 3.1 科技 → 军事（5 条，最大混淆对）

典型错例：

- 「中国成功发射遥感四十二号01星 卫星进入预定轨道」→ 预测军事（真值科技）
- 「SpaceX星舰完成第四次轨道试飞 成功实现可控溅落」→ 预测军事（真值科技）
- 「我国首艘国产大型邮轮爱达魔都号完成首航」→ 预测军事（真值科技）

**成因**：航天发射、舰船等主题在训练模板中与军事类关键词高度同域（「卫星」「运载火箭」在科技词池，「航母」「舰队」语体在军事模板），且评测样本使用了训练词表外的实体名（遥感四十二号、星舰、爱达魔都号），模型只能依赖语体线索，偏向了语体更强的军事类。

**对上线的含义**：航天/军工交叉题材是系统性弱区。若业务中此类内容占比高，应在训练数据中补充该交叉域的标注样本，或在下游对「科技/军事」两类设置置信度阈值走人工复核。

### 3.2 军事 → 时政（4 条）

典型错例：

- 「国防部回应南海问题：中国对南海诸岛及其附近海域拥有无可争辩的主权」（真值时政→预测军事，反向亦有 1 条时政→军事）

**成因**：国防外交类表述天然跨「时政/军事」两域；训练数据中国防部、外交部模板各自封闭，未覆盖这类交叉表述。注意该混淆对是双向的（军事→时政 4 条、时政→军事 1 条），说明模型对两类边界的认知模糊而非单向偏置。

**对上线的含义**：时政/军事边界模糊属于标签体系层面的固有歧义（同一条新闻人类标注者也会有分歧）。建议业务侧接受这两类之间的小比例互混，或在标注规范中明确「涉及国防外交的归时政」并在训练数据中对齐。

### 3.3 社会 → 财经（3 条）与 房产 → 财经（3 条）

典型错例：

- 「中央经济工作会议定调2025年宏观政策将更加积极有为」（真值时政→预测财经）
- 「发改委和财政部联合发布超长期特别国债发行方案」（真值时政→预测财经）

**成因**：财经类 precision 仅 0.70、recall 1.00——即财经类「来者不拒」，把含经济政策表述的时政/社会/房产样本都吸了过去。训练数据中财经模板覆盖大量政策类关键词（减税降费、专项债、财政赤字），与宏观政策类时政样本边界重叠。

**对上线的含义**：财经类误报偏高。若下游按类别路由工单，财经通道会有约 30% 的杂质（主要来自时政/房产）。可通过增加时政类「经济工作会议/宏观政策」模板、或在财经类训练样本中剔除纯政策表述来改善。

### 3.4 小结

32 条错例全部集中在 4 类语义交叉域（科技/军事、时政/军事、财经/时政、财经/房产），不存在因模型能力不足导致的随机错误（验证集已收敛到 1.0000）。提升路径明确：扩充训练模板对交叉域的覆盖，而非换更大的模型。

### 4.2 复现命令

```bash
cd inference

# 一键全流程（venv → 依赖 → 训练 → 评测），结果自动落盘 results/
bash run.sh

# 已有 checkpoint 时跳过训练
bash run.sh --skip-train

# 等效分步命令
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python train.py --epochs 3 --samples 400 --seed 42 --max-length 48
python eval.py --output results/eval_results.json
```

首次运行需下载 hfl/chinese-roberta-wwm-ext 权重（约 400MB）；网络受限时可 `export HF_ENDPOINT=https://hf-mirror.com`。

### 4.3 复现性说明

- 训练数据由 `seed=42` 模板引擎确定性生成，训练使用固定种子（Python random + torch），同版本依赖下训练→评测数字完全可复现。
- 若同事环境的 torch/硬件与上表不同，个别样本的 argmax 可能出现浮动；出现差异时优先核对 `requirements.txt` 版本与 `checkpoints/training_meta.json` 中的超参是否一致。
- 数字回溯链：`results/train_run.log`（训练）→ `checkpoints/training_meta.json`（超参）→ `results/eval_results.json`（指标+逐条预测）→ `results/eval_run.log`（评测日志）。
